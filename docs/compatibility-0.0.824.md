# Mirasim 0.0.824：4.5.0 适配说明

0.0.824 的 shell ABI 为227，Claude启动身份、模型目录及前端状态同步结构均有变化。旧4.4.0引擎会在写入前停止，并报告 `Claude runner fingerprint: expected one match, found 0`。4.5.0沿用同一套Git自动更新入口，为这些结构增加适配，继续提供Codex速度、Claude Fast和Claude Ultracode三项控制。

## 如何更新脚本

不需要重新下载版本压缩包。等当前任务结束，从系统托盘完全退出Mirasim，再运行原来的 **01-安装或修复.bat**。启动器检查仓库 `main` 后，补丁引擎应显示 **4.5.0**；安装完成后重新打开Mirasim。

“脚本已是最新”仅表示本地提交与仓库一致；兼容检查仍由补丁引擎执行。安装文件被Mirasim占用时，会回滚本次写入并提示退出后重试。只关闭聊天窗口可能仍有后台进程，应从系统托盘退出。

**02-查看状态.bat** 根据当前程序文件检查安装状态。**04-导出兼容报告.bat** 的报告仍保存在 `%LOCALAPPDATA%\MirasimControls\diagnostics`。不要手动修改 `releases/<提交号>` 内的缓存文件。

## 保留的新版行为

### Claude启动身份

824新增 `launchVolatile`，用于显式列出启动时生成的短期值。计算进程复用身份时，原生逻辑会把其中长度至少16的有效字符串替换为统一标记 `<boot-secret>`，并归一化MCP配置内容、额外参数及环境值。启动参数合并还会去重聚合这些值。

这项归一化只参与身份计算，实际启动参数和环境仍保留原值。4.5.0保留原生函数及值的来源，不自行生成或扩大volatile列表。Fast、Ultracode、推理强度和其他有意义的启动配置仍需独立影响进程身份。

### 模型目录与配置校验

824在保存Qwen设置时，按所选模型实际提供的强度档位（rungs）校验选择。模型目录还会回落到可用的默认强度，只为路由模型暴露相应配额字段，并采用新的原生模型序列化函数。适配保留这些校验、回落和字段范围，继续在原目录中传递新增控制字段。

Claude Fast的原生参数构造、配置读取和合并顺序保持不变，适配不需要替换这些函数。

### 前端状态与错误

824的catalog reducer先构建配置对象，再通过深度相等判断跳过重复更新。适配把 `fastMode`、`ultracodeEnabled`、`serviceTier` 和 `serviceTiers` 四个字段保留在被比较的对象中，使控制项发生变化时正常刷新，同时保留重复状态跳过更新的原生行为。

共享应答函数还会从错误帧保留 `refusal` 信息。适配继续调用新版应答函数，保留其错误语义，不用旧函数替换它。

原生Select菜单现在等待定位结果就绪，再把当前选项滚动到可见位置。适配保留这个等待顺序；紧凑输入栏、推理强度、上下文与Provider的关键函数结构和792一致。

## 控制语义

- Codex继续使用“跟随配置、标准、Fast、Ultrafast”下拉选择，独立于推理强度。
- Claude Fast继续明确开启或关闭；未显式选择前保留原生配置继承。
- Claude Ultracode继续独立启用，保留所选推理强度；关闭此开关不抹除其他原生来源的模式设置。
- 设置作用于后续执行，不中断已有模型任务，也不改写原生Claude或Codex配置文件。
